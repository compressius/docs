The `cmx` command-line interface provides everything you need to manage your local gateway, connect coding agents, monitor token usage, and update CMX. Run `cmx --help` to see the commands available in your installed version.

---

## Get Started

### `cmx login`

Sign in and pair this device with your CMX account through the browser.

```bash
cmx login
```

---

### `cmx setup`

Sign in and connect detected coding agents. This is the recommended command to run the first time you install CMX — it handles browser sign-in, gateway startup, and agent connection in a single guided flow.

```bash
cmx setup
```

<Tip>
  Run `cmx setup` immediately after installation. It combines login, gateway
  start, and coding agent connection so you don't have to run each step
  separately.
</Tip>

---

### `cmx harness enable`

Route a detected coding agent through CMX so its traffic passes through the local compression gateway.

```bash
cmx harness enable
```

---

### `cmx serve`

Run CMX in the current terminal as a foreground process. The gateway stays active for as long as the terminal session remains open.

```bash
cmx serve
```

---

### `cmx doctor`

Diagnose configuration and connectivity issues. This command inspects your installation, checks gateway connectivity, and reports any problems it finds.

```bash
cmx doctor
```

<Tip>
  The output of `cmx doctor` may include local file paths and configuration
  details. Review it carefully and remove any sensitive information before
  sharing it with support.
</Tip>

## Start and Stop

### `cmx`

Open the interactive terminal interface. Use this to manage connections, configure providers, and adjust preferences through a keyboard-driven UI.

```bash
cmx
```

---

### `cmx start`

Start CMX as a background process. The gateway continues running after you close the terminal.

```bash
cmx start
```

---

### `cmx stop`

Stop the background CMX process and point your connected coding agents back to their direct connections.

```bash
cmx stop
```

Before CMX shuts down the gateway, it restores the configuration of every coding agent routed through CMX. Your agents keep working while CMX is stopped. CMX also saves a reconnect record, so the next `cmx start` routes the same agents through CMX again. CMX only reconnects an agent if its configuration is unchanged since the stop.

Stopping CMX from the interactive terminal interface, or sending `SIGINT` or `SIGTERM` to the gateway, also restores your agents.

Running `cmx stop` again after a successful stop is safe. The second run changes nothing and keeps the reconnect record from the first stop.

If CMX cannot restore an agent's configuration, for example because you edited that file by hand, `cmx stop` refuses to shut down the gateway. It prints the agent and the path of the configuration file it could not restore. Fix the conflicting edits in that file, then run `cmx stop` again.

<Note>
  CMX does not connect agents automatically while the gateway isn't running. Agents are never pointed at an inactive local port.
</Note>

---

### `cmx status`

Show the current CMX status, including whether the gateway is running and how it is configured.

```bash
cmx status [flags]
```

**Flags:**

| Flag     | Description                            |
| -------- | -------------------------------------- |
| `--json` | Output status in machine-readable JSON |

**Examples:**

```bash
# Human-readable status
cmx status

# Machine-readable JSON output
cmx status --json
```

## Usage and Diagnostics

### `cmx stats`

Show today's token and compression statistics, including tokens handled, estimated net savings, and provider activity.

```bash
cmx stats
```

---

### `cmx logs status`

Check whether opt-in raw logging is currently enabled on this device.

```bash
cmx logs status
```

---

### `cmx dashboard`

Open the CMX web dashboard in your default browser. The dashboard shows account-level usage history across all your devices.

```bash
cmx dashboard
```

## Connections and Maintenance

### `cmx harness list`

List all detected coding agent harnesses on this device.

```bash
cmx harness list
```

---

### `cmx harness verify`

Verify that saved coding-agent connections are still valid and reachable.

```bash
cmx harness verify
```

If an agent still points at CMX while the gateway isn't running, the command reports it and exits with an error. Run `cmx stop` to restore those agents to their direct connections.

---

### `cmx harness disable`

Restore the original harness configuration for all connected coding agents, removing CMX from their request path.

```bash
cmx harness disable [harness]
```

Pass a harness name, such as `codex`, `opencode`, `claude`, `cline`, `aider`, or `antigravity`, to restore only that agent.

<Tip>
  `cmx uninstall` restores your coding agents automatically. If you remove CMX
  manually, run `cmx harness disable` first so your agents continue working
  normally after CMX is removed.
</Tip>

---

### `cmx sessions purge`

Delete expired local sessions to free up space and remove stale session data.

```bash
cmx sessions purge
```

---

### `cmx upgrade`

Check whether a newer version of CMX is available, or download and install the update immediately.

```bash
cmx upgrade [flags]
```

**Flags:**

| Flag        | Description                               |
| ----------- | ----------------------------------------- |
| `--install` | Download and install the available update |

**Examples:**

```bash
# Check for an available update
cmx upgrade

# Download and install the update immediately
cmx upgrade --install
```

---

### `cmx logout`

Sign out of your CMX account and clear all locally stored credentials from this device.

```bash
cmx logout
```

---

### `cmx uninstall`

Completely remove CMX from this device. The command restores every connected coding agent to its direct connection, stops the gateway, removes the systemd or launchd user service, deletes CMX configuration and data, and removes the CMX executable. `cmx remove` and `cmx rm` are aliases.

```bash
cmx uninstall [flags]
```

**Flags:**

| Flag            | Description                                 |
| --------------- | ------------------------------------------- |
| `--yes`, `-y`   | Uninstall without the confirmation prompt   |
| `--force`, `-f` | Same as `--yes`                             |
| `--keep-config` | Keep the CMX configuration directory        |
| `--keep-data`   | Keep session history and the usage database |

If any agent cannot be restored, CMX aborts and stays installed. See [Uninstall](/uninstall) for details and the manual purge fallback.

## Global Flags

These flags are available on every `cmx` command.

| Flag              | Description                     |
| ----------------- | ------------------------------- |
| `--help`, `-h`    | Show help for a command         |
| `--version`, `-v` | Print the installed CMX version |

**Examples:**

```bash
# Print the installed CMX version
cmx --version

# Show top-level help
cmx --help

# Show help for a specific command
cmx harness --help
```

---

<Note>
  Not all flags may be listed here. Run `cmx --help` or `cmx <command> --help`
  for the complete list of flags available in your installed version.
</Note>
