Connect the Antigravity CLI (`agy`) to CMX so requests from Antigravity pass through the local gateway. CMX compresses eligible context in the background, reducing the tokens sent to CloudCode (and Gemini, when a `GEMINI_API_KEY` is set) as your Antigravity sessions grow.

<Note>
  **Prerequisites:** CMX must be installed and signed in on your device. Antigravity (`agy`) must already be installed and signed in. CMX does not replace your Antigravity account.
</Note>

<Steps>
  <Step title="Set Up CMX">
    Run the guided setup command to sign in, start the local gateway, and detect your coding agents:

    ```bash
    cmx setup
    ```

    Follow the browser sign-in prompt. Once setup completes, the CMX gateway starts at `127.0.0.1:17322` and is ready to accept connections.
  </Step>

  <Step title="Connect Antigravity">
    Enable the Antigravity harness. Both `antigravity` and the short alias `agy` are accepted:

    ```bash
    cmx harness enable antigravity
    ```

    CMX installs a small wrapper next to the real `agy` binary. The wrapper sets:

    - `CLOUD_CODE_URL` to `http://127.0.0.1:17322/route/cloudcode`, so CloudCode traffic flows through CMX.
    - `GOOGLE_GEMINI_BASE_URL` to `http://127.0.0.1:17322/route/gemini` when `GEMINI_API_KEY` is present, so Gemini traffic also flows through CMX.

    The wrapper then execs the real `agy` binary, so command-line arguments and interactive behavior are unchanged. On Windows, CMX writes a `.cmd` wrapper alongside a `.real.exe` copy of the original binary so the shim works from any shell.
  </Step>

  <Step title="Verify the Connection">
    Confirm that Antigravity is routing through CMX correctly:

    ```bash
    cmx harness verify
    ```

    Run `agy` as you normally would. Then check CMX for activity:

    ```bash
    cmx stats
    ```

    New requests should appear in the stats output. If you see activity, the connection is working.
  </Step>
</Steps>

<Note>
  Short conversations may show little or no compression. Savings grow with longer sessions as eligible older context accumulates. Compare stats across a full coding session to get a representative picture.
</Note>

## Automatic reconnection

CMX runs a periodic harness check roughly every 24 hours. If an Antigravity update replaces the `agy` binary and removes the wrapper, the next `cmx` command notices the drift and re-installs the wrapper automatically. You do not need to run `cmx harness enable antigravity` again after each upgrade.

## Disconnecting

To remove the wrapper and route Antigravity directly to CloudCode again:

```bash
cmx harness disable antigravity
```

CMX deletes the wrapper (and the `.cmx-hash` / `.cmx-backup` metadata) so the next `agy` invocation runs the real binary directly.

## Troubleshooting

If requests from Antigravity are not appearing in `cmx stats` after a session:

1. **Check that the harness is enabled** — run `cmx harness list` and confirm Antigravity shows `enabled (routing through CMX)`.
2. **Confirm the wrapper is on your PATH** — run `which agy` (or `where agy` on Windows). It should point at the wrapper that CMX installed, not directly at the original binary.
3. **Run the diagnostics command:**

   ```bash
   cmx doctor
   ```

For more detailed guidance, see the [troubleshooting guide](/troubleshooting). If the issue persists, contact support with your CMX version, OS, and a description of what happened.
