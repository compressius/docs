Connect Cline to CMX so requests from the Cline VS Code extension pass through the local gateway. CMX compresses eligible context in the background, reducing your provider token usage across longer coding sessions, without requiring any changes to how you use Cline.

<Note>
  **Prerequisites:** CMX must be installed and signed in on your device. Cline must already be installed in VS Code with a configured model provider. CMX does not replace your provider account; you continue managing your provider sign-in through Cline as usual.
</Note>

<Steps>
  <Step title="Set Up CMX">
    Run the guided setup command to sign in, start the local gateway, and detect your coding agents:

    ```bash
    cmx setup
    ```

    Follow the browser sign-in prompt. Once setup completes, the CMX gateway starts at `127.0.0.1:17322` and is ready to accept connections.
  </Step>
  <Step title="Connect Cline">
    Open the CMX terminal UI and connect Cline to your provider:

    ```bash
    cmx
    ```

    1. Navigate to **CONFIG → Cline**.
    2. **Refresh the provider list** to make sure your configured provider appears.
    3. Select the provider you use in Cline.
    4. Click **Connect**.
    5. Reload the VS Code window so Cline picks up the new routing through CMX.

    Cline will now send all requests through the CMX gateway instead of directly to your provider.
  </Step>
  <Step title="Verify the Connection">
    Confirm that Cline is routing through CMX correctly:

    ```bash
    cmx harness verify
    ```

    Send a request from Cline as you normally would. Then check CMX for activity:

    ```bash
    cmx stats
    ```

    New requests should appear in the stats output. If you see activity, the connection is working.
  </Step>
</Steps>

<Note>
  Short conversations may show little or no compression. Savings grow with longer sessions as eligible older context accumulates. Compare stats across a full coding session to get a representative picture.
</Note>

## Troubleshooting

If requests from Cline are not appearing in `cmx stats` after a coding session:

1. **Reload the VS Code window** so the new routing takes effect.
2. **Check the selected connection** by opening CONFIG → Cline in CMX and confirming the correct provider is connected.
3. **Run the diagnostics command:**
   ```bash
   cmx doctor
   ```

For more detailed guidance, see the [troubleshooting guide](/troubleshooting). If the issue persists, contact support with your CMX version, OS, and a description of what happened.
