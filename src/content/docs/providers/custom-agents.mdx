# Connect custom AI coding agents for token compression

Custom AI coding agent token compression allows developers building bespoke agentic loops or using third-party tools (such as LangChain, AutoGen, CrewAI, DSPy, Cursor, or proprietary CLI scripts) to reduce input token volume and lower LLM API expenses. By changing your client's API base URL to the local CMX gateway on `127.0.0.1:17322`, CMX compresses multi-turn context and prunes repetitive tool outputs across OpenAI, Anthropic, and Gemini protocols.

While CMX provides dedicated, automated integrations for [six official clients](/providers/overview), any tool or framework that allows setting an API base URL can connect to CMX without code modifications.

## Why custom agentic loops burn tokens rapidly

Autonomous agentic loops and agent frameworks operate through iterative reasoning-action cycles:
- Executing code against compilers, linters, and test suites.
- Fetching documentation, browsing web pages, and querying internal vector databases.
- Accumulating thousands of lines of intermediate JSON payloads and tool outputs.

Because autonomous agents submit their entire conversational history on every turn, input token counts grow rapidly. Without local compression, a 40-step agent run can easily consume millions of input tokens, driving up costs and degrading model attention on earlier project constraints.

## How to connect any custom agent to CMX

Start the local CMX gateway:

```bash
# Start the local gateway and verify status
cmx start
cmx status
```

Configure your framework or tool's base URL environment variable (e.g., `OPENAI_BASE_URL` or `ANTHROPIC_BASE_URL`) or settings to point to the appropriate CMX loopback route:

| Upstream protocol | Example CMX base URL | Supported target services |
| --- | --- | --- |
| **OpenAI-compatible API** | `http://127.0.0.1:17322/route/openai/v1` | OpenAI (GPT-4o, o1, o3), OpenRouter, DeepSeek, Groq |
| **Anthropic Messages** | `http://127.0.0.1:17322/route/anthropic` | Anthropic (Claude 3.7 Sonnet, Claude 3.5 Haiku, Opus) |
| **Google Gemini (REST / SSE)** | `http://127.0.0.1:17322/route/gemini` | Google Gemini API (Gemini 2.5 Flash, 2.5 Pro) |
| **Local Ollama** | `http://127.0.0.1:17322/route/ollama` | Local Ollama running at `127.0.0.1:11434` |

Replace `openai`, `anthropic`, `gemini`, or `ollama` with any supported upstream ID. Your native API keys stay with your client—pass them as standard `Authorization: Bearer <token>` or `x-api-key` headers.

## Advanced request-level routing

CMX supports multiple methods to dynamically route traffic from custom clients:
- **URL Path routing:** `/route/<provider>/...` or `/provider/<provider>/...`
- **Query parameter:** `?cmx_provider=<provider-id>`
- **HTTP Header:** `X-CMX-Provider: <provider-id>`
- **Dynamic upstream endpoint:** `X-CMX-Base-URL: https://custom-endpoint.example.com/v1`

## Native Google Gemini adapter

CMX includes a native adapter for Google Gemini. If your tool communicates directly via the Gemini REST format (`/v1beta/models/{model}:generateContent` and `:streamGenerateContent`), point it at:

```text
http://127.0.0.1:17322/route/gemini
```

CMX transparently handles server-sent events (`alt=sse`), extracts usage from `usageMetadata`, and preserves `functionCall`, `functionResponse`, and `thought` parts without breaking tool calls. If your tool uses Gemini's OpenAI-compatible endpoint instead, route to `http://127.0.0.1:17322/route/gemini/v1`.

## Automatic endpoint path normalization

If your custom agent framework sends bare endpoints like `/chat/completions` or `/responses` without a `/v1` prefix, CMX automatically normalizes the path by prepending `/v1` before forwarding to the upstream provider:

```text
# Both paths route cleanly to https://api.openai.com/v1/chat/completions:
http://127.0.0.1:17322/route/openai/chat/completions
http://127.0.0.1:17322/route/openai/v1/chat/completions
```

## Verify live token compression

1. Run a request or start an agent loop in your custom tool.
2. Check real-time token compression and gateway activity:

```bash
# View live session statistics and token reduction
cmx stats
```

## Return to direct routing

To disconnect your custom client, restore its original base URL in that tool's settings or unset your environment variables. Then stop the gateway if no other clients require it:

```bash
cmx stop
```
