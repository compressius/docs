# ChatGPT Desktop token compression & alternatives

ChatGPT Desktop token compression explains how developers can optimize AI context and token usage when using OpenAI ChatGPT subscriptions for coding tasks. While the standalone ChatGPT Desktop application does not expose custom network proxy settings, developers can achieve full token compression and cost optimization by connecting their ChatGPT subscription through the official OpenAI Codex CLI routed via CMX.

Developers frequently search for ways to reduce context limits, avoid rate limits, and compress conversation history in ChatGPT Desktop during extensive software development projects.

## Why standalone ChatGPT Desktop cannot be proxied directly

The official ChatGPT Desktop application (for macOS and Windows) is a packaged native client that communicates directly with OpenAI's closed endpoints. Unlike developer-focused coding agents:
- It does not expose configurable `OPENAI_BASE_URL` or custom proxy environment variables.
- It does not provide access to local configuration files for network re-routing.
- Consequently, it does not appear in `cmx harness list`.

## Recommended solution: Route ChatGPT subscription via Codex CLI

If you want the benefits of your ChatGPT subscription (Plus, Team, or Enterprise) combined with CMX local token compression and autonomous coding agent workflows, the recommended approach is to use **OpenAI Codex CLI**:

1. Install and log in to OpenAI Codex using your ChatGPT account:
   ```bash
   codex login
   ```
2. Connect Codex's ChatGPT sign-in mode to the local CMX compression gateway:
   ```bash
   cmx providers codex connect chatgpt
   ```
3. Restart Codex and verify that traffic is compressing:
   ```bash
   cmx stats
   ```

By routing through Codex's `chatgpt` mode, your existing ChatGPT subscription covers model usage while CMX intercepts local requests on `127.0.0.1:17322`, compressing repetitive tool outputs, summarising historical context, and preventing context rot.

For complete setup instructions, see the [Codex integration guide](/providers/codex).

## Other tools with configurable API base URLs

If you are using a third-party developer tool, IDE extension, or custom agent framework that allows configuring an OpenAI-compatible API base URL, you can route it through CMX directly. Point its base URL to:

```text
http://127.0.0.1:17322/route/openai/v1
```

For full details on endpoint normalization and path routing, see [Custom clients](/providers/custom-agents).
