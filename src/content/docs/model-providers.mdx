# Upstream model providers & API cost savings

CMX reduces per-token API expenses and prevents context window exhaustion across major upstream model providers, including OpenAI, Anthropic, Google Gemini, OpenRouter, DeepSeek, and Groq. By compressing repetitive conversation context on `127.0.0.1:17322` before forwarding requests, CMX cuts input token charges without exposing private code or credentials.

A **model provider** is the cloud or local service that executes neural network inference and bills for token consumption. A **coding client** (such as Codex, OpenCode, Claude Code, Aider, Antigravity, or Cline) is the development environment where you code. CMX leaves your native API keys securely inside your coding client while routing traffic through its local compression engine.

## How CMX saves money across model pricing models

Different model providers utilize distinct pricing and rate limit tiers. CMX provides tangible operational advantages across all of them:

### 1. Frontier Pay-Per-Token Models (OpenAI & Anthropic)
Flagship reasoning models (such as OpenAI o1/o3 or Anthropic Claude 3.7 Sonnet) have premium input token rates. Because autonomous agents resend the entire message history on every step, a 40-turn task can resubmit 100k+ input tokens 40 times. CMX replaces obsolete spans with concise summaries, saving significant dollars per task.

### 2. High-Throughput & Budget APIs (DeepSeek & OpenRouter)
Even on low-cost providers like DeepSeek-V3, autonomous agents that loop indefinitely can consume millions of tokens over a weekend. CMX enforces context ceilings and prunes failed test traces, preventing runaway billing surprises.

### 3. Rate-Limited Endpoints (Groq & Cloud Providers)
Fast inference providers like Groq enforce strict Tokens-Per-Minute (TPM) limits. By compressing input tokens by 30% to 60%, CMX keeps your coding agent below rate-limit thresholds, preventing frustrating HTTP `429 Too Many Requests` interruptions.

### 4. Local Models (Ollama)
For developers running local models on Apple Silicon or NVIDIA GPUs, large context windows severely degrade generation speed (Time-To-First-Token) and can exceed hardware VRAM. CMX compresses context locally, keeping prompt processing fast and lightweight.

## Connecting an upstream provider via your client

CMX upstream IDs tell the local gateway how to format and forward requests. To connect an upstream provider:

1. Configure your API key and chosen model inside your coding client first.
2. Inspect discovered providers:
   ```bash
   cmx providers <client> list
   ```
3. Connect the displayed provider ID:
   ```bash
   cmx providers codex connect api
   # or
   cmx providers opencode connect <provider-id>
   ```
4. Restart your coding client and check live savings with `cmx stats`.

## Supported protocols & compression paths

CMX natively compresses requests adhering to the following industry-standard protocols:
- **OpenAI Chat Completions (`/v1/chat/completions`)**
- **OpenAI Responses (`/v1/responses`)**
- **Anthropic Messages (`/v1/messages`)**
- **Google Gemini REST (`:generateContent` / `:streamGenerateContent`)**

Requests following other formats pass through transparently without modification. For custom proxy architectures, see [Custom clients](/providers/custom-agents). To understand compression algorithms and privacy guarantees, see [How compression works](/how-compression-works).
