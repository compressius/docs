# Configure CMX

Most people only need **CONFIG** in the terminal interface:

```bash
cmx
```

Use it to inspect discovered clients, connect a provider, disconnect one, and change local display or compression preferences. Restart a coding client after its routing settings change. For command-line control, use `cmx providers <client> list`, `connect`, and `disconnect`; see the [CLI reference](/cli-reference).

## Where settings live

CMX's own configuration is `config.json` in the following directory:

| Operating system | Default configuration | Default local data |
| --- | --- | --- |
| Linux | `~/.config/cmx/config.json` | `~/.local/share/cmx/` |
| macOS | `~/Library/Application Support/cmx/config.json` | `~/Library/Application Support/cmx/` |
| Windows | `%APPDATA%\cmx\config.json` | `%LOCALAPPDATA%\cmx\` |

Linux respects `XDG_CONFIG_HOME` and `XDG_DATA_HOME`. The data directory holds local state such as usage records, cached summaries, and connection metadata. The CMX provider map stays in CMX's `config.json` when client routing is restored; it is not a backup of your coding client's settings.

CMX uses JSON, **not** `cmx.config.toml`. A small example of the relevant fields is:

```json
{
  "gateway": { "listen_addr": "127.0.0.1:17322" },
  "compression": {
    "min_context_tokens": 1000,
    "preserve_tail_tokens": 1000
  }
}
```

CMX fills in other defaults when loading its configuration. Keep the gateway on loopback. Do not place provider API keys in this file. Use the native coding client or its environment for credentials. After editing CMX settings, restart the gateway with `cmx restart` and restart affected coding clients if their routes changed.

## Compression controls

The default minimum context is **1,000 estimated tokens** per request, and the recent protected tail is **1,000 tokens**. CMX also requires sufficient eligible context and a proposal that passes policy and economics checks; reaching the minimum alone does not guarantee a summary.

The **CONFIG** screen can enable selected local optimizations, including duplicate tool-output pruning, removal of historical error output, truncation of long tool output, stripping eligible historical thinking, and the local content vault. These options have different effects. The lossless vault is **off by default**; when enabled, it archives original content from selected prune or truncate actions in the local SQLite store. Review [Security and data handling](/security) before enabling it.

The default protected tool list includes `task`, `skill`, `todowrite`, `todoread`, `write`, `edit`, and `apply_patch`. Recent context, instructions, opaque content, and complete protected tool exchanges are also safeguarded by policy. See [How compression works](/how-compression-works).

## Gateway lifecycle

```bash
cmx start      # background process for this user
cmx status
cmx stop       # restore managed client routes, then stop
```

`cmx start` launches a detached process. It does not automatically install a login service. If restoration fails during `cmx stop`, CMX keeps the gateway running and reports the client conflict.
